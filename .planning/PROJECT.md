# Vantage

## What This Is

A multi-agent LangGraph platform that takes a free-text research request (ticker, investment thesis, or financial question) and produces a fully cited `ResearchMemo` in minutes via seven specialized AI agents backed by a multi-source RAG pipeline (SEC EDGAR, FRED, yfinance, NewsAPI, arXiv, user PDFs). Designed for individual investors and small teams who need institutional-quality research without the institutional budget. The standout differentiator: a structured Contradictions panel that explicitly surfaces where agents disagree — no silent conflict resolution.

- WebSocket live progress panel + async Celery research task execution (replacing v1.0's sync-only run)
- Persistent follow-up chat sessions grounded on memo text (no RAG re-query)
- Structured FinancialMetric storage enabling isolation-forest anomaly detection
- Watchlist monitoring with NEW_FILING, PRICE_MOVE, and SCHEDULED alert rules
- Full observability: LangSmith traces, per-agent cost breakdown, RAGAS offline eval

**Out of scope (deferred to v3):** SENTIMENT_SPIKE alert rule, cross-memo Anomaly/Risk queries, admin roles, email/push notifications, social/sharing features, real-time market data streaming, mobile app, FinBERT fine-tuning (see Out of Scope below).

## Context

- **Tech stack**: Python 3.11, FastAPI, LangGraph, ChromaDB (single collection), PostgreSQL, Celery + Redis (async tasks + beat scheduling), React/TypeScript, Docker Compose. Observability: LangSmith (tracing), RAGAS (offline eval), scikit-learn (isolation-forest anomaly detection)
- **LLM**: Groq (Llama 3.3 70B versatile) — free tier ~6,000 tokens/min (12,000 TPM on some accounts); parallel agent execution exhausts this in seconds without rate limiting. Rapid consecutive research runs against the same plan can still 429 externally — not a regression, an account-tier limit
- **Data sources**: All free — SEC EDGAR (full-text search API, queried via `q`, quoted for exact-phrase match), FRED, yfinance, NewsAPI free tier, arXiv API, user PDF uploads
- **Agent architecture**: 7 agents, all shipped as of v2.0 (Phase 5) — Orchestrator (routing, disambiguation), FundamentalAnalysis, SentimentNLP, RiskAssessment, MacroSector, ComparableCompanies (true parallel fan-out), Synthesis (fan-in, owns memo status + Contradictions)
- **Codebase size at v2.0 ship**: ~31,700 LOC Python (`app/` + `tests/`) + ~2,200 LOC TypeScript (`frontend/src`), 687 tests passing (8 skipped: env-gated live tests)
- **Deployment target**: Not yet decided in detail, but Vercel is frontend-only (React) — the FastAPI+Postgres+Redis+ChromaDB backend needs a platform that supports multi-service, stateful deployments (e.g. Railway, Render, Fly.io) once a production deploy is planned
- **Prior work**: Full domain grilling session (40+ questions resolved), comprehensive PRD in docs/PRD.md, domain glossary in CONTEXT.md, 17 GitHub issues published

## Constraints

- **Rate limit**: Groq free-tier ~6,000 tokens/min — shared async token-bucket rate limiter is day-one, non-negotiable; no code path calls Groq directly
- **EDGAR policy**: User-Agent header (`Vantage/1.0 vishwak.vel@gmail.com`) required on every EDGAR request — omission causes silent 429/403
- **Code boundary**: All external API calls live in `app/services/` only — never inline in agents
- **String constants**: Section string values defined in `app/ingestion/section_constants.py` only — never as inline literals
- **Test boundary**: No real API calls in tests — mock at `services/` boundary only
- **Git**: Feature branches only — never commit to main directly
- **Secrets**: Everything via `.env` (gitignored) — no hardcoded credentials

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| ResearchMemo lifecycle: PENDING → RUNNING → COMPLETE \| PARTIAL \| FAILED | PARTIAL = memo exists with gaps (agent failures); FAILED = no usable memo (Orchestrator-level failure) | ✓ Good — implemented in Phase 4, `_compute_memo_status` covers all 4 status combinations |
| Synthesis agent owns ResearchMemo.status | Only agent with full cross-agent visibility | ✓ Good |
| Declarative routing table (not LLM-driven) | Deterministic dispatch; LLM routing adds latency and failure surface for no benefit at this scale | ✓ Good — plain `add_edge` linear graph in Phase 4, no conditional routing |
| ClarificationResponse not persisted; no ResearchMemo until disambiguation resolved | Avoids orphaned memos in PENDING state forever | ✓ Good — verified in Phase 3 (D-06 all-or-nothing gate) |
| Section strings are plain-string convention; constants live in `app/ingestion/section_constants.py` only | Prevents inline literals from drifting across codebase | ✓ Good |
| All Groq API calls go through a shared async rate limiter | Groq free-tier ~6,000 tokens/min; direct calls will 429 under parallel agent execution | ✓ Good — CI-enforced import guard (`tests/test_boundaries.py`) proves no direct `groq` import outside `groq_client.py` |
| EDGAR client must include User-Agent on every request | EDGAR API policy; requests without User-Agent are blocked silently | ✓ Good — held up against real EDGAR calls during Phase 2's live re-verification |
| FinancialMetric is first-class persisted table, upsert key (ticker, metric_name, period) | Required for isolation-forest anomaly detection; can't run on raw AgentOutput fields | — Pending, not yet built (Milestone 2 scope) |
| Single Chroma collection (not per-ticker or per-user) | Metadata filtering handles scoping; multiple collections add operational complexity for no retrieval benefit | ✓ Good — `where={"user_id": ...}` isolation proven live against real ChromaDB in Phase 2 re-verification |
| RAGAS evaluation is offline-only (Celery beat job) | Per-memo online eval adds latency; offline golden set sufficient for retrieval quality signal | — Pending, not yet built (Milestone 2 scope) |
| Sessions ground follow-ups on memo text; no RAG re-query | Follow-ups are about the memo, not new research; re-querying pollutes context | — Pending, not yet built (Milestone 2 scope) |
| AgentOutput stored in its own table (not on AgentTask) | Outputs are large; storing on AgentTask row would bloat queries | ✓ Good |
| Company entity (ticker PK) normalizes ticker strings across all tables | No raw ticker strings in FKs; avoids case/exchange prefix drift | ⚠️ Revisit — the FK is correctly enforced by the schema, but no code path ever *created* a Company row for a brand-new ticker (`ticker_resolver` only matches against an in-memory seed list, never persists it). Every first-time ingest of an unseeded ticker hit a `ForeignKeyViolation`. Fixed 2026-07-03 by adding `_ensure_company_exists()` upsert in `ingestion_service.py`, but this was invisible to the mocked test suite (tests pre-seed a `Company` fixture) — worth a similar audit before Milestone 2 adds more FK-dependent tables (FinancialMetric, Watchlist) |
| chromadb client and server images should be version-pinned together, not independently | Discovered 2026-07-03: client `0.5.23` calls `/api/v2/auth/identity` on connect, which server image `chromadb/chroma:0.5.0` doesn't serve — every real ChromaDB call failed despite passing mocked tests | New — bumped server image to `0.5.23` to match the client pin; apply the same client/server version discipline to any future pinned service (e.g. if Postgres or Redis client libraries gain version-gated features) |
| EDGAR's Full-Text Search API (`efts.sec.gov`) must be queried with `q` (quoted for exact-phrase match), not `entityName` | `entityName` is not a recognized EFTS parameter at all — every query using it returned a bare `500 Internal Server Error` from EDGAR, silently blocking all ingestion. Corrected 2026-07-06 (Phase 6 live verification); this row previously stated the opposite (claimed `entityName` was the fix) — that was wrong and is corrected here. The primary-document filename is separately, correctly found via `FilingSummary.xml`'s `<Report instance="...">`, not directory-listing order (exhibits are listed before the primary doc) | Fixed 2026-07-06 — verified directly against the live `efts.sec.gov` API |
| Every new external service client gets one env-gated live smoke test (D-01 pattern) | Repeats the Phase 2 lesson: mocked tests alone missed product-critical bugs (wrong params, wrong field names). Opt-in via `RUN_LIVE_TESTS=1` keeps default `pytest` runs hermetic | ✓ Good — established in Phase 5 (`tests/live/`); caught a real bug on first use (arXiv now permanently redirects `http://` → `https://`, and httpx doesn't follow redirects by default) that all mocked tests missed |
| Each parallel fan-out agent node opens its own `AsyncSession` via `session_scope()`, never shares one | Concurrent LangGraph nodes writing through a single shared session hit asyncpg's "another operation is in progress" | ✓ Good — Phase 5; confirmed necessary again when end-to-end tests initially shared one session and hit the same collision |
| Every module-level singleton wrapping a persistent async client (DB engine, EDGAR/news/arXiv/Groq httpx clients) must expose a `reset_*()` that Celery's `run_research_task` calls before each `asyncio.run(...)` | A client created inside one task's event loop raises `RuntimeError: Event loop is closed` if reused in a later task's loop — `reset_session_factory()` solved this for the DB engine in Phase 6 (06-03) but was never extended to the 4 HTTP clients, causing intermittent live-run failures | ✓ Good — fixed 2026-07-06; confirmed 0 occurrences under normal single-run conditions after adding `reset_news_client`/`reset_arxiv_client`/`reset_edgar_client`/`reset_groq_client` |
| Section-heading detection in the EDGAR chunker must require BOTH a line-start position AND title-shaped text following the "Item N" token — a bare regex match anywhere in flattened text is not enough | A mid-sentence cross-reference like "...see Item 1A of our most recent Annual Report..." was silently reclassifying real MD&A content (gross margin, tax rate, dividends) as Risk Factors disclosure. Real EDGAR filings also separate the item number from its title with `&#160;` HTML entities, not a literal space — `html.unescape()` must run AFTER tag-stripping, never before (an early `&lt;`/`&gt;` decode risks corrupting subsequent tag parsing) | ✓ Good — fixed 2026-07-06 (`app/ingestion/chunker.py`), verified against Apple's real 10-Q markup after re-ingestion |
| ChromaDB retrieval for a real authenticated user must search `{user_id, ""}` (private + public), never just the exact `user_id` | Public EDGAR filings are stored under `user_id=""`; scoping strictly to the real user's UUID meant a logged-in user's research run could never see EDGAR content that had just been ingested for them — invisible until a real end-to-end run with a real user was attempted | ✓ Good — fixed 2026-07-06 (`app/services/vector_store.py::dense_query`), isolation test updated to assert the `$in` list never contains another user's id |
| Shared `.input` CSS class must have a real border/background, not `border: transparent` + `background: var(--color-surface)` | Every `.input` nested inside a `.panel` (same `--color-surface` background) was completely invisible — no border, identical fill color. Invisible to the full passing test suite and to `tsc`/`vite build` (a rendering/contrast defect, not a type or logic error); only surfaced when the real user tried to use the Phase 10 Watchlist "Add ticker" field during UAT and reported "clicking Add does nothing" (an empty-input submit is also a silent no-op by design, compounding the confusion) | ✓ Good — fixed 2026-07-28 (Phase 10 UAT), `.input` now uses `background: var(--color-bg)` + a real `border-color`; affects every input in the app (Plan ID, login, chat, watchlist), not just the new Watchlist form |
| `.planning/` is gitignored | Keeps planning artifacts out of the shipped repo history | ⚠️ Revisit — recurring cost: worktree-isolated executors write SUMMARY.md under their own `.planning/` copy, and `git worktree remove` silently destroys it since it was never tracked. Hit Phase 7 (07-02, 07-05) and recurred at Phase 8 (08-01/03/04/06) — all reconstructable from commit history + VERIFICATION.md, but each recurrence costs a milestone-close investigation. Fix before v3: either untrack-but-don't-gitignore `.planning/phases/`, or have executors write summaries to a path outside the worktree |
| `fred_client.py` keeps its own module-level singleton `httpx.AsyncClient`, untouched since Phase 5 | Mirrors the pre-Phase-6-fix `EDGARClient` pattern | ⚠️ Revisit — same class of "Event loop is closed" risk that `reset_session_factory()`/`reset_news_client`/`reset_arxiv_client`/`reset_edgar_client`/`reset_groq_client` fixed for every other Phase 5-6 client; `fred_client` was never given a `reset_fred_client()`. Confirmed as a live risk during Phase 12 verification but not yet triggered in practice — add the same reset hook before it causes an intermittent MacroSector failure |
